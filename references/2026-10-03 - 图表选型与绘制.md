# 图表选型与统一绘制

2026-10-05 复用入口：最终已确认样例见[图族索引](2026-10-04%20-%20已确认图族与复用索引.md)，新数据的共用工具见[图形工具接口](2026-10-04%20-%20图形工具接口.md)。本文件中旧模板的限制只适用于该模板；不要把历史待评审措辞覆盖后续已确认样例。

日期：2026-10-03。状态：HaosuNaki 本轮采用建议。字体与四种基础配色沿用已确认方案。以下选型是针对阅读页的默认策略，不是唯一正确图形。

跨数据图、结构图、机制图解的共同风格及选型入口见[作图总则与选型路径](2026-10-03%20-%20作图总则与选型路径.md)。本文件负责需要数值编码的数据图，不能只因素材带有数字就跳过读者问题判断。

## 1. 先问目的，再看数据

制作前写出一句读者问题，再确认观察对象、指标、单位、时间/类别、数据来源及缺失值。数据类型相同也可能因阅读任务不同而选不同图。

- 一条数值只需关键数值与解释，不自动生成图表。
- 要查精确值或核对多种单位时，优先表格。
- 没有数值、只解释步骤或关系时，使用信息图解，不虚构数字画统计图。
- 一个图题只承载一个主要问题；不同问题可用同一组数据画两张图。

## 2. 选型矩阵

| 读者问题 | 所需数据 | 默认图形 | 必须说明/避免 |
| --- | --- | --- | --- |
| 谁更高、谁更低 | 类别＋同口径数值 | 横向条形图；必要时排序 | 长度从零起；有自然顺序时保留原序 |
| 随时间怎样变化 | 真实时间＋数值 | 折线图；期间发生量可用柱图 | 时间间距真实，缺失留断点，不平滑虚构趋势 |
| 总体由什么组成 | 互斥且可加总的分项 | 单条堆叠条形图 | 分项构成同一整体；总量和单位明确 |
| 各组结构如何不同 | 多个总体的分项 | 100% 堆叠条形图 | 标分母和各组总量；占比不能替代规模 |
| 数值集中在哪里 | 一批连续观测值 | 等宽分箱直方图 | 说明分箱；样本量和异常值不隐藏 |
| 哪组波动更大 | 多组原始观测值 | 箱线图，少量样本叠加原始点 | 标样本量和箱/须定义，不能只画均值 |
| 两个指标是否相关 | 同一对象的成对数值 | 散点图 | 观察单位一致；相关不能直接解释为因果 |
| 前后改变了多少 | 同一对象的两个可比状态 | 哑铃图；名次迁移用斜率图 | 口径可比；不能据此描述中间过程 |
| 哪些增减造成结果 | 起点＋可加总贡献＋终点 | 瀑布图 | 起点＋增减必须等于终点；非加性比例不能相加 |
| 高于或低于目标多少 | 实际值与共同基准的差值 | 发散条形图 | 零点代表基准；百分点与百分比变化分清 |
| 数量从哪里流到哪里 | 来源、去向和对应权重 | Sankey；类别迁移可用 Alluvial | 只有阶段总量不能推出个体流向 |
| 空间位置有什么影响 | 地理范围＋口径明确的指标 | 比率用设色地图；总量用比例符号 | 单纯地区排名用条形图；缺失不当零 |
| 需要逐项查数 | 多字段记录与明确单位 | 表格 | 按列的语义对齐，保留缺失/不适用标记 |
| 估计有多不确定 | 点估计＋有定义的区间 | 点＋区间；预测用区间带 | 注明区间类型和水平，不写成确定上下限 |

饼/环图仅作为少量组成关系的例外，类别差异接近、需精确比较时使用条形图。雷达图、双轴组合图和3D图不作为默认模板；确有任务收益时再单独说明尺度和读法。

选型方法参考 [FT Visual Vocabulary](https://github.com/Financial-Times/chart-doctor/tree/main/visual-vocabulary)。流量图的数据条件见 [EU Sankey and Alluvial](https://data.europa.eu/apps/data-visualisation-guide/sankey-and-alluvial-diagrams)；区间含义见 [EU Error bars](https://data.europa.eu/apps/data-visualisation-guide/error-bars-and-the-cone-of-uncertainty)。

## 3. 统一图形风格

以下是可复用的 HaosuNaki 默认值，可因密度做局部调整，不能牺牲标签可读性。

- 图题沿用宋体中文标题；图内中文标签用 PingFang SC，英文标签用 JetBrains Mono；展示数值 Georgia，缺失时 Lora。
- 图题放在图上方，读者问题或有证据支持的结论优先；单位/口径紧接图题，来源和限制紧接图底。
- 默认纸白背景、开放图面，不给每张图再套大卡片。整组图题、图、控件、图注继承所属阅读列。
- 图内文字默认16px，轴刻度14px起；它们承担短标签作用。完整解读使用正文尺度，不随图形缩小。
- 主数据线2px、辅助网格1px；点形用于识别观测值，不能每个位置都堆满数值标签。布局随宽度重新计算。
- 轴、网格使用辅助线色；可见数据及关键边界不能依赖接近底色的浅线。无需的纵横网格、外框、背景渐变省略。
- 同一测量尺度上的数据口径与单位一致；散点图的x/y可以使用不同单位，须分别标明。大数适度用万/百万等单位并标出。相同指标的小数精度一致；不要为伪精确补很多位小数。
- 优先直接标签；图例与图紧邻，颜色有明确含义。手机调整标注密度或拆图，不把整张图当图片缩到字不可读。

### 颜色按语义使用

- `focus`：显式指定重点对象；用色服从设计基准 §2，不能覆盖已有领域含义。没有色义冲突时才默认蓝＋灰；不得自动挑最大值或第一项。
- `category`：按设计基准 §2 的区分度原则选色并绑定稳定类别 ID；不机械取前三色，不用相近色硬凑。跨图和筛选保持身份映射；类别过多时优先分面、标签或表格。
- `single`：只有一个测量序列、无需区分多个类别的图，例如一条时间序列或一组分布。整个序列同等着色，不暗示某个点更重要。它不是多个类别比较时灰化其他对象的替代办法。
- 数值色阶按设计基准 §2：领域含义和冷暖关系优先于默认蓝色方案；量值顺序、真实基准、同组尺度和缺失规则仍须满足。默认色值不证明任意插值或新图已验证。
- 瀑布图按业务语义和个案确认选择增减色，保留正负号与图例；期初/期末中性。无特定色义时可用默认方向色，不能自动把增减当成好坏。

标题、轴与标注方法参考 [IBM Design basics](https://www.ibm.com/design/language/data-visualization/design/basics/)。上述像素、字体和品牌色是 HaosuNaki 的采用值。

## 4. 数据诚实性约束

1. 条形/组成图以零为长度基线；折线与散点可使用合理的非零范围，但轴域和刻度必须清楚。
2. 折线按真实x间距定位；未知值保持缺口，不自动补零或连接缺失区间。
3. 组成必须能形成同一整体；总数为零时不计算百分比；负值不能混入普通100%组成图。
4. 瀑布图逐项加总并核对终点；散点不自动拟合“因果趋势”。
5. 预测与观测、估计与事实通过明确文字/线型区分；不确定区间写清定义。
6. 图中的所有数字能在邻近数据表或来源中找到；展示演示数据时明确写“虚构演示”。

轴和缺失值原则参见 [Carbon Axes and labels](https://www.carbondesignsystem.com/building-blocks/data-visualization/axes-and-labels)。

## 5. 可复用实现与验收

内置绘图模板用于常见图形；具体 JSON 契约见 [绘图模板使用](2026-10-03%20-%20绘图模板使用.md)。模板支持范围之外的图仍按本规范选型和绘制，不能把示例误当成所有图都已有现成实现。

采用三层验收：

- 数据：单位、映射、缺失、零点、加总正确；排序不改类别身份。
- 组合：标题/图/控件/来源属于一个完整阅读单元，不忽宽忽窄；图确实比正文更清楚。
- 呈现：1440/390/320视口查看；数据标签不越界，关键系列不靠颜色单独识别；默认状态可读，键盘可操作。

渲染通过不等于研究结论成立，也不等于不同设备字体或PDF分页已经通过。需要打印时单独导出并逐页检查。
