# 选图判断树：问题、证据、表达

日期：2026-10-04。状态：用户已认可“FT 表达目的 → Data to Viz 数据结构筛选”的组合方向；以下具体分支与推荐为本轮工作方法，待真实案例检验，不代表逐项采纳参考资料中的全部图表或外观。

本方法为 HaosuNaki 场景综合，服务数据对比、机制解释、情景分析。不是 Claude、Apple 或 IBM 的内部方法，也不声称树的分支严格 MECE 或能算出唯一最优图。材料可支持多个任务：先确定当前图的主问题，复杂任务分成相互对应的多图。

## 1. 方法依据与职责

- [Brehmer 与 Munzner 的任务类型研究](https://www.cs.ubc.ca/labs/imager/tr/2013/MultiLevelTaskTypology/)区分为什么做任务、处理什么输入输出、如何完成任务。本方法据此先写读者问题，再谈表现手段。
- [Munzner 的嵌套设计与验证模型](https://www.cs.ubc.ca/labs/imager/tr/2009/NestedModel/NestedModel.pdf)区分领域问题、数据与任务抽象、视觉编码与交互、算法实现。选错问题不能靠美化补救；页面能运行也不证明选图正确。
- [FT Visual Vocabulary](https://github.com/Financial-Times/chart-doctor/tree/main/visual-vocabulary)展示按比较、变化、分布等阅读目的组织图形的方法；[IBM Carbon v10 图表类型](https://v10.carbondesignsystem.com/data-visualization/chart-types/)明确先识别目的再选图。后者是公开历史版指导，不代表其最新目录。
- [Data to Viz](https://www.data-to-viz.com/)从数值、分类、混合、时间、地图与网络等输入结构筛选候选图形。我们将这个输入筛选放在表达目的之后，两者取交集，不直接照搬网站的全部偏好。

以下分支、优先级、缺数据处理和研究例子是 HaosuNaki 的应用判断。查具体数值图条件继续读[图表选型与绘制](2026-10-03%20-%20图表选型与绘制.md)，研究场景继续读[研究与产品选图](2026-10-03%20-%20研究与产品选图.md)。不把参考资料目录直接当作我们的强制模板清单。

## 2. 主判断树

先写：**读者需要对哪些对象，判断什么关系或差异？** 未有结论时写问题，不预设哪一个对象更好。“哪个更优”须先有评价指标与约束。能展示已有材料不等于已回答原问题；只有平均值可以比较均值，不能据此判断稳定性。

```text
读者要完成什么？
├─ 查一个事实 / 精确字段
│  ├─ 一句话或一个值已足够 → 文字 / 指标＋口径
│  └─ 多对象共用字段要核对 → 表格
├─ 看数量的模式或差异 → FT表达目的 → 数据结构筛选 → 数值图候选（§3）
├─ 理解如何运作、谁与谁有关 → 机制图分支（§4）
└─ 改变假设，看结果怎样变 → 情景分支（§5）
   ↓ 每个候选图都必须经过输入检查
所需数据 / 关系 / 规则是否具备？
├─ 具备 → 定义位置、长度、颜色、箭头的含义
└─ 不具备 → 说明缺口；改为可支持的表格、定性说明或明确标注的假说
   ↓
静态表达是否足够？
├─ 足够 → 直接呈现
└─ 不足 → 按查看细节、切换范围、改变输入选择交互（§6）
   ↓
按已确认主题绘制，并分别验收选型、数据、视觉与行为
```

“查精确值”和“观察模式”可同时成立，使用图＋数据表；地图、区间、分组常作为主图的补充。不要为了走完树而丢掉原任务。

## 3. 数值图：先表达目的，再数据结构

第一层按 FT 的九类目的定位：**偏差、相关、排名、分布、时间变化、数量大小、部分与整体、空间、流动**。这是数值图的导航，不是包含全部机制和交互的总分类。不确定性、分组、观测/计算身份是贯穿多个目的的附加属性。

第二层借用 Data to Viz 的数据结构思路筛候选，依据下表检查类型、变量数量、顺序及记录粒度：

| 输入结构 | 在已选目的下如何筛选 |
|---|---|
| 一个数值变量的原始样本 | 分布目的才进入直方、ECDF、箱线等；只有一个汇总值则回到指标说明 |
| 一个分类＋一个汇总数值 | 数量/排名通常进入条形或点图；同一数据不能据此虚构各类分布 |
| 一个分类＋每类多个原始样本 | 若问题是组间波动，比较分布；若只需均值，说明汇总并保留样本口径 |
| 两个配对数值变量 | 相关目的可用散点；无配对记录不能拿两组无对应的数值硬配 |
| 三个或更多变量 | 先判定第三变量是身份、数值还是时间，再考虑颜色/分面/面积；不自动塞进气泡或3D |
| 真时间＋数值 | 时间目的再看单/多序列、频率、期间量/时点值和缺失；类别有序不自动等于时间 |
| 同整体分项或层级 | 先检验可加性、互斥性与分母；有层级不意味着需要树图面积编码 |
| 地理数据或网络边 | 位置/连接必须与问题相关；带权流动需来源—去向记录，只有节点清单不足以画Sankey |

第三步才从以下候选中选最简单且可读的表达；这是任务与输入的交集。

| 主问题 | 默认候选 | 输入检查 / 何时换一种 |
|---|---|---|
| 谁更高，差距多大？ | 点图或横向条形；同对象前后两值用哑铃 | 同口径、单位、分母；条形长度从零起。精确字段多则用表格 |
| 谁排在前面，名次如何变化？ | 排序条形 / 点图；名次迁移用斜率图 | 排名依据明确、保留并列；关心绝对差距时同时保留数值，不把名次差当数量差 |
| 随时间怎样变？ | 折线；各期间发生量可用柱图 | 必须是真时间，间距与缺口真实；两时点不能捏造中间曲线 |
| 差距相对哪个基准？ | 发散条形 / 点与基准线 | 基准明确；偏差零有真实含义，百分比与百分点分清 |
| 组成如何不同？ | 同整体堆积 / 多组100%堆积 | 同一整体、分项互斥且可加；比较具体分项高低时改并排条/点 |
| 增减如何形成结果？ | 瀑布 | 起点＋可加总贡献＝终点；只有相关因素不能当贡献 |
| 数值如何分布、尾部多长？ | 原始点 / 直方 / 箱线 / ECDF | 原始样本或相应统计充分；只知道均值不能画出分布，区间须说明定义 |
| 两个变量有关吗？ | 散点；分组或分面检查混杂 | 同一观察单位的成对记录；相关不当因果，汇总不冒充个体 |
| 来源如何流向去向？ | 带权流量图；精确比较可用转移矩阵 | 需要来源—去向记录与权重；只有阶段总数不能推出流向 |
| 位置是否影响理解？ | 地图；只看地区高低用条形 | 地理关系必须是问题核心，区域比率、总量分别选编码 |
| 估计有多不确定？ | 点＋区间 / 轨迹＋区间带 | 区间定义与计算依据；可作为其他图的附加表达，不从点估计猜区间 |

候选图通常不止一个。先排除输入不支持的，再优先选择能清楚对齐当前比较关系、在目标尺寸下可读的表达；如两种均成立，说明取舍。类别过多时用排序、分面或可见筛选，不用越来越多的颜色补救。

## 4. 机制图：箭头、区域和顺序分别代表什么？

| 主问题 | 默认候选 | 必须说明 |
|---|---|---|
| 接下来做什么，条件如何分支？ | 流程图；条件组合多时决策表 | 动作、分支条件、返回和终点；未知条件保留未知 |
| 谁负责，如何交接？ | 泳道流程 | 参与方、交接物、职责边界和等待 |
| 谁调用谁，如何往返？ | 时序图 | 发送者、接收者、请求/响应、同步/异步、失败；顺序不冒充时长 |
| 对象从什么状态变成什么状态？ | 状态转换图 | 状态、触发事件、守卫条件、回退；账号状态与KYC状态分开 |
| 系统由什么组成，边界在哪里？ | 架构 / 层级图 | 包含、职责、接口；容器必须对应真实边界 |
| 对象如何关联或依赖？ | 实体关系 / 依赖网络 / 关系矩阵 | 关系类型、方向与基数；普通关联不画成因果 |
| 排队、并行、等待或循环如何运行？ | 队列、分叉汇合、时间带、反馈示意 | 调度与汇合规则、触发和停止；长度若表示时间必须按比例 |
| 为什么可能导致某个结果？ | 机制剖面 / 因果假说图 | 区分已支持关系与假说，逐边说明依据；画箭头不建立因果证明 |

同一图不要让同一种箭头同时表示请求、时间先后和因果。需要多种关系时用分面或明确线型图例。机制图并非天然只能是方框；环形、局部放大、前后状态等结构按真实规则定制。

## 5. 情景分析：先定义模型，再添加控件

| 条件 | 表达 | 边界 |
|---|---|---|
| 没有可计算规则 | 假设—预期—待验证的情景表 / 定性机制图 | 不提供伪精确数字或自动计算控件 |
| 一个输入变化，有计算规则 | 敏感性曲线；只有几个离散方案时用点图/表 | 明确输入范围、固定假设、阈值和结果单位 |
| 两个输入共同变化 | 计算网格热图 / 情景矩阵 | 每个单元来自同一模型，轴与其余固定量可见 |
| 多个输入变化 | 基准场景＋少量可比场景 / 条件分面 | 区分单因素与联合变化；不以二维图冒充覆盖所有组合 |

观测、机制假说和模型输出分别标识。情景曲线不代表预测概率；没有概率模型不能把几条情景包络称为置信区间。

## 6. 交互是第二次判断

交互不是第五种数据类型，也不自动比静态图更好。

- 查看细节：选中对象或显示注释；关键信息默认可见，不能只靠悬停。
- 切换范围：筛选、分面选择或比较口径；默认尺度尽量可比，变化需说明。
- 改变输入：只有存在明确规则才重算；控件 → 数据 → 图形 → 解读同步更新，提供初始情景和重置。
- 静态已经清楚时保持静态；必要交互支持键盘、手机与可复制的当前参数。

## 7. 两个例子与一张最小决策记录

**同一份AI评测材料：** 问谁成功率高，用可比点图并显示样本口径；问为什么失败，用错误类型与机制关系，假说标未知；问改变题型权重后排名如何，用有公式的重加权情景并单列为计算。不能用一张蓝色柱图回答三种问题。

**同一份账号材料：** 问谁有权限，用主体—资源—操作的权限矩阵；问授权如何求值，用条件流程；问账号怎么从冻结恢复，用状态转换。具体规则取自材料，不由模板补造。

每次作图在工作记录写五项即可：
1. 读者问题。
2. 证据身份与可用输入：观测 / 假说 / 规则 / 计算。
3. 首选表达、取舍与缺失时的处理。
4. 位置、长度、颜色、箭头编码什么；交互改变什么。
5. 验收：回答问题 / 保真 / 可读 / 可操作。

配色在选型之后确定，并按设计基准 §2 先保证业务含义、冷暖关系和类别区分，再考虑品牌色。单一重点、类别身份和量值编码分开；丰富颜色不能替代正确结构。
