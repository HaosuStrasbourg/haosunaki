# 定制SVG与交互实现

默认用离线HTML承载SVG图面、可重排说明与必要交互。共用视觉基准，内容决定几何结构。

## 1. 绘制方式

| 情况 | 做法 |
| --- | --- |
| 少量固定对象，强调精确布局/注释 | 人工布局内联SVG；坐标显式可审阅，不必搭自动布局引擎 |
| 输入会改变数量、位置、归属或曲线 | 纯函数计算结果与几何，再绘制SVG |
| 长说明、表单和字段比较 | HTML＋CSS Grid/Flex，与SVG配合；不塞进SVG text |
| 标准统计任务，现有组件能准确表达 | 复用模板；不为模板改数据，质量不足可定制 |
| 已有项目库确能解决复杂坐标/密集数据 | 复用已有依赖并套用本风格；新依赖按任务授权，不默认引CDN |
| 关系密集、信息过多 | 先拆总览/局部或筛选；缩放拖动不能替代信息组织 |

矩形、点、路径、区域、时间带、集合与圆环都是可选表达；不强制等大节点或直角连线。模板的能力限制不等于业务或数据限制。

流程／机制图按[方框连线图规范](2026-10-03%20-%20方框连线图规范.md) §1 选择执行型或解释型密度，并沿用 §2：真实条件用菱形，保留完整节点名称，明确真实起止范围，优先短直线与就近汇合。调试／评审可加定位编号；正式稿默认移除并清理相应文字引用，内部稳定 ID 保留。显示时编号不占正文行，内容仍在完整形状内居中。架构对象或普通状态不因名称含“判断”而误用流程形状。

## 2. 构图顺序

1. 定主比较轴、逻辑方向、真实分组与标注空间。相同任务的分面保持同单位、尺度、排序与对应位置。
2. 布置主要对象再接线。连线接到正确边界或端口，避开无关对象和文字；回路/分支保留专用通道。箭头方向必须有语义。
3. 就近标注条件、单位与短解释。交叉不代表连接，汇合点明确画出；边界只包含真实成员。
4. 线型、符号和颜色在同组图中含义一致；有假说边时标明未验证。机制示意注明非比例，数据尺度真实。
5. 简化阅读层级：短图题 → 图面及必要控件 → 一句解读与来源。复杂假设可另展开，关键条件默认可见。
6. 查看实际视觉重心。图面承担主要解释，不能前置四层方法说明把有效图面挤到很小。

颜色统一按设计基准 §2 的业务语义、冷暖关系和类别区分优先级选择；默认品牌色不能覆盖含义。机制对象描边与普通/强调分组按其角色处理，统计填充由数据编码决定。需要补充颜色时验证实际区分度，不用模板限制反向改变语义。

16px短标签、14px辅助、主关系线约2px、辅助线约1px、普通节点圆角约8px是起点。完整解释使用正文角色。不要用固定高度、裁切和缩字修复排版。

## 2.1 总览与局部展开

当读者既要知道某环节在全流程中的位置，又要看该环节的内部步骤时，采用“总览＋局部展开”；不要把两幅独立流程并排后简单连成前后步骤。

- **先确定展开对象。** 总览保留完整主流程，只强调要展开的一个节点；局部视图使用同名边界，内部只包含这个对象的步骤或成员。两处是同一对象的不同详细程度，不是两次执行。
- **对应关系和执行顺序分开画。** 总览节点与局部边界用无箭头引线、对应标记或明确导航关联；同页并排可用两条细引线连接对应边角，形成放大关系。图注明确引线含义，不把引线接到内部第一步或用普通流程箭头表示“放大”。具体位置、线型和角度依版面调整，不固定成唯一模板。
- **边界与输入输出一致。** 父流程连到总览节点，局部执行线留在展开边界内；局部起止覆盖同一输入和输出。不要从右侧末步又跨图连接左侧下一步，让同一过程看起来执行两遍。被省略的关键判断、异常或返回路径仍须在局部图交代。
- **每个视图保持相近粒度。** 总览回答“用在哪里”，局部回答“里面怎么走”；旁注回答“为什么这样选”。样式配置、示例清单和解释段落不自动变成串行步骤。入口文案用直接动作，如“放入初稿”；图内短标签，说明就近放旁边。
- **验收。** 不读长段说明也能定位展开源；对象名称、范围、输入输出对应；展开引线不会被误读为执行箭头；缩成实际展示大小仍可读。展开布局与视觉样张需单独评审，不因写入规则就视为用户确认。

参考：[Camunda 子流程折叠与展开](https://camunda.com/bpmn/reference/#activities-subprocess)提供过程封装与边界依据；[C4 Container diagram](https://c4model.com/diagrams/container)提供同一对象逐层放大的范围依据。两条无箭头引线是本体系用于说明图的构图选择，不是 BPMN 或 C4 强制符号。严格 BPMN 图仍沿用其顺序流、边界与事件记法。

## 3. 共用图面骨架

构建器遇到 `.hn-figure` 时内嵌 `assets/figure-tools.css/js`。复用标签/数值/连线等角色，不把CSS当规定拓扑的模板。当前图的特殊布局可用局部类补充。

```html
<main>
  <figure class="hn-figure" aria-labelledby="figure-heading">
    <h2 id="figure-heading">写明这张图回答的问题</h2>
    <div class="hn-tools" aria-label="当前图操作">
      <!-- 按任务选用原生 label / select / input / button -->
    </div>
    <div class="hn-figure-frame">
      <svg id="research-svg" viewBox="0 0 720 360" role="img"
           aria-labelledby="research-title research-desc">
        <title id="research-title">图名及当前场景</title>
        <desc id="research-desc">关系、数值或机制的等价说明。</desc>
        <!-- 根据当前输入绘制 -->
      </svg>
    </div>
    <p class="hn-insight" aria-live="polite"><!-- 当前结果与原因 --></p>
    <figcaption class="caption">口径、来源与限制。</figcaption>
  </figure>
</main>
```

`.hn-label`=短标签，`.hn-small`=辅助，`.hn-value`=独立数字，`.hn-edge`=关系线，`.hn-node`=普通对象，`.hn-focal`=显式重点。SVG文字继承既有中英混排栈。数值类不要套住整段中文。`id`、marker、clipPath按图加前缀，桌面/手机版也不能重名。

## 4. 手机重新组织，不能只缩放

- 固定viewBox搭配width:100%会缩小文字；检查 `fontSize × 实际宽度/viewBox宽度`，不能只检查CSS声明16px。
- 根据容器宽度计算方向和坐标，维持对象/关系/状态；长说明放可重排HTML，不能删分支条件。
- 复杂图可有独立桌面/手机构图，使用同一数据和模型；只让可见版本进入辅助技术，导出指向可见版本。
- 保留拓扑比重排更重要时使用图内局部滚动：可读字级、提示、键盘聚焦、等价文字/表格。页面本身不横向溢出。
- ResizeObserver只更新图面，输入控件保留DOM和焦点；重排不重置业务条件。

## 5. 输入、计算、视图分离

```js
const state = { /* 输入，不存另一份人工填写的结论 */ };
function evaluate(input) {
  // 只按给定公式/规则计算，返回结果、原因、未满足条件。
}
function render(input, result) {
  // 同一result更新图面、读数、原因与可访问描述。
}
function update(patch) {
  Object.assign(state, patch);
  render(state, evaluate(state));
}
```

- 数字、注释、路径高亮不能各维护一份矛盾逻辑。改变参数后解释为何改变；若结果不变也应正确解释。
- 情景交互注明固定量、输入范围、公式与假设；缺失不是0，超出适用范围不要外推。误差/置信区间必须来自资料或明确且成立的计算方法，不能装饰性添加。
- 查看详情无需假造模型。通常原生按钮/选择器控制图面，比只给SVG绑定click更易保证键盘访问。
- 控件有标签、焦点和当前值，触屏与键盘能得到关键内容。温和live region更新摘要，避免每次重复朗读整图；默认图面独立成立。
- 初始场景、重置、空结果与边界输入有可理解反馈；不出现NaN或无解释空白。
- 动画仅用于解释运动/时间，提供暂停/逐步与reduced-motion。重建innerHTML不等于节点过渡已实现。
- 用户文本用textContent或SVG DOM设置；JSON嵌入script时将 `<` 转义为 `\u003c`，不把业务输入拼成可执行HTML。

## 6. SVG导出与其他媒介

需要独立图时可调用：

```js
await HNFigure.exportSVG(document.getElementById('research-svg'), 'research-state.svg');
```

可选第三参数 `{transparent:true}`，默认纸白。调用方提供原生按钮及可见的成功/错误状态，函数不自动加工具栏。导出当前SVG的静态快照，固化计算样式并携带页面已有的开放字体。先等待字体就绪，图面必须含当前场景、关键条件、单位与标签；图外正文不会自动导出，SVG不保留交互。

本机中文和Georgia只引用不打包；内嵌开放字体的版权与OFL全文保存在SVG的metadata中；页面缺少对应许可时拒绝打包该字体。导出辅助拒绝外部图片、跨图引用、脚本/事件、foreignObject与SVG动画，不能静默丢内容。必要时为导出生成无交互的等价SVG并单独核对。

PNG/PDF需要实际生成与检查。GitHub README不能运行原HTML交互；按用户需要选择SVG/PNG与完整HTML的组合，不静默降级。

## 7. 验收

- **逻辑**：手算正常例、会改变结论的分支、边界和复位。数据核对单位/分母/比例/缺失，机制核对方向/条件，情景核对公式和假设。
- **信息**：能看出比较对象、参照、原因与限制；无数据不冒充统计，有关联不暗示因果。
- **画面**：实际渲染桌面、390、320；标签不遮挡截断，箭头端点正确，边界无误包；图题、控件和图注共用版心；检查实际字体和显示字级。
- **操作**：真实点击/键盘变更关键输入，结果与解释同步；手机重排不丢状态。仅测试任务需要的行为，不追求穷举所有模板。
- **导出**：提供按钮就真实下载并重新打开，核对当前状态、标题、标签、箭头、字体回退和离线资源。

最终列出真正检查过的载体/行为；未检查PDF、其他设备字体或读屏器时如实说明，不声称全面认证。

## 8. 可运行的研究示例

`assets/examples/research-body.html` 是一次独立选图测试产生的完整正文：合成AI评测数据的总体/分组比较、任务权重机制、共同权重情景、重置和SVG导出。直接用build_html.py的 `--body` 指向它即可生成离线成品。它复用当前样式资源，不另带一份字体。

参考其中的输入/计算/渲染分离、稳定类别和手机几何重排，不把其题目、数据、章节数或横条构图套到其他研究。数据图与结构图仍按读者问题重新选择；此例不验证所有图形和业务场景。
