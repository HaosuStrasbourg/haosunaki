2026-10-04 选型入口：先走[选图判断树](2026-10-04%20-%20选图判断树.md)的“问题 → 候选 → 输入检查 → 交互”路径；本文件保留跨图语言和实现方向。新判断树属于工作方法，图表样式仍需独立评审。

日期：2026-10-03。用户确认纳入的两项原则：所有图具有统一风格；根据内容判断何时使用哪种图。以下把原则落实为默认工作规则。默认视觉基础沿用既有描边、配色候选与五类字体；2026-10-04 用户确认配色以业务含义、冷暖关系和类别区分优先，完整规则见设计基准 §2。尺寸仍为工作建议。

## 1. 统一视觉语言，图形结构服从问题

风格一致来自共享的视觉角色和绘制方法。不同问题可以用不同结构；不能为统一外观，把队列、时间变化、并行关系都套成相同的方框链。

| 统一项 | 默认规则 | 可以变化的部分 |
| --- | --- | --- |
| 底色与层次 | 纸白画布与分类节点，类别色描边；中性辅底只作必要分组；统计填充按数值编码，深色正文与克制辅助线 | 真实边界、留白和分组数量 |
| 五类字体 | 沿用设计基准的标题、正文与展示数字角色；图内短标签16px，辅助刻度14px起 | 已确认标题的排版、标签换行、标签密度；不靠缩小整图解决拥挤 |
| 线与形 | 数据线和主要关系线2px，辅助网格1px；普通结构节点圆角8px；不用装饰阴影、渐变、立体效果 | 条、点、线、容器、时间轴、环形或分叉等形态；定量条形保持尺度准确，不强套节点圆角 |
| 颜色语义 | 按每张图的任务选择重点、分类或单一序列；不用颜色装饰所有对象 | 强调不得覆盖领域颜色；平等类别用可辨的固定身份色；无强调需求的结构图保持中性 |
| 图文位置 | 图题在上，口径/单位紧接图题，短注释就近，来源/限制在图底；控件紧邻所影响的图 | 细节可展开，关键条件与结论默认可见 |
| 阅读尺度 | 标题、图、控件、图注全组默认共用720px阅读列；窄屏重新排列 | 复杂内容可整组用宽区、拆图或局部滚动，并保留等价文字 |

具体色值、字体回退与字号见[设计基准](2026-10-03%20-%20设计规范.md)。上表用于跨图复核，不建立另一套重复维护的色值表。完整解释仍使用正文尺度；机制图不强制具有坐标轴、网格或等大节点。

### 跨图保持什么不变

- 同一对象名称和 ID 稳定。分类颜色跨图、重排和交互保持一致；重点采用不冲突的视觉通道，不能冒充类别身份或覆盖领域色义。
- 同一关系在同组图中使用相同箭头/线型含义；虚线、容器、方向都要能解释，不在相邻图里悄悄变义。
- 用于直接比较的多幅定量图保持单位、口径、刻度范围和排序可比。确需不同尺度时清楚标出；机制示意不伪装成按比例数据图。
- 同组图的标题位置、标签层级、数字精度、线宽和留白节奏一致。统一风格不要求每幅图使用全部强调色、相同节点数量或相同拓扑。
- 状态首先用明确文字或符号表达；状态配色按业务语境定义，不将品牌分类色自动解释成成功、失败或风险。

## 2. 从读者问题选择表达

研究优先任务继续读[研究与产品选图](2026-10-03%20-%20研究与产品选图.md)，区分数据证据、机制假说与情景计算；定制构图和交互按[定制SVG与交互实现](2026-10-03%20-%20定制SVG与交互实现.md)执行。下面是通用入口，不是穷尽目录。

先确定主要问题，再检查输入是否支持；不能仅凭“有数字”“出现时间”“已有某模板”决定图形。

| 主要阅读任务 | 首选表达 | 必须具备的输入或含义 |
| --- | --- | --- |
| 查精确字段，逐项核对 | 表格；仅一个关键值时用数值＋解释 | 字段、单位、期间、缺失标记；一句话已足够时不画图 |
| 比大小、趋势、组成、分布、相关、贡献或不确定性 | 数据图，继续按14类选型表选择 | 同口径观测与必要数据；图形编码真实数值 |
| 明确下一步和判断分支 | 流程图 | 步骤、先后、分支条件与方向 |
| 明确系统层次、职责和归属 | 架构图 | 对象、真实边界、层级及接口 |
| 明确对象之间的关联 | 关系图 | 对象、关系名称与是否有方向；不能把普通关联画成因果 |
| 解释谁等待、谁先被处理 | 队列机制图 | 排队/优先规则、处理方向、当前处理对象；顺序图不暗示处理时长 |
| 解释等待多久、间隔如何变化 | 时间轴或退避机制图 | 时间/间隔规则；若长度编码时长就按比例，否则注明非等比例示意 |
| 解释如何拆分并行、何时汇合 | 分叉—并行—汇合图 | 分支、启动条件、等待全部/任一等汇合规则；不能默认所有分支都成功 |
| 解释如何回到前一步、何时停止 | 循环/反馈图 | 反馈对象、返回路径、触发条件和退出条件；没有反馈依据不画闭环 |
| 解释操作前后哪里变了 | 前后状态图；必要时加可操作演示 | 可比状态、触发动作和变化规则；共同对象保持位置与标识，不补造中间过程 |

任务是比较数量时，继续读[图表选型与绘制](2026-10-03%20-%20图表选型与绘制.md)；任务是流程/架构/关系时，读[方框连线图规范](2026-10-03%20-%20方框连线图规范.md)。机制图解按本表选择结构，继承共同视觉规则后单独绘制和验收。

### 相同素材，问题不同，图也不同

- 重试记录：比较各次耗时用数据图；解释下一次是否重试用条件流程；解释等待间隔翻倍用退避时间轴。
- 服务清单：解释归属用架构图；解释请求经过哪些服务用流程图；比较各服务延迟用条形图。
- 并行任务：解释执行与等待用分叉汇合图；比较各分支完成时间用条形图或时间轴。没有来源去向权重时，不用Sankey假装流量。

一个图解决一个主问题。材料同时支持多个问题时，拆成总览与局部图，稳定对象命名；不把多个语义堆到同一套箭头或颜色上。

## 3. 在生成和验收中执行

作图前在工作记录中简要写清：**读者问题 → 图形选择及理由 → 必要输入 → 颜色含义**。不用把这四项做成每页给读者看的配置面板。

交付前做两项检查：

1. **选型成立**：图确实回答该问题；所需输入存在；位置、长度、箭头和颜色没有暗示未经证实的数量、时间或因果。
2. **同族一致**：将同页图放在一起核对字体角色、底色、线宽、标签、类别身份和图注位置；再检查无重叠、无文字截断、手机仍可读。

现成模板仍为6类数据图与3类结构图；定制绘图能力不受此数量限制。机制、状态、区间、复合图按内容用SVG与HTML/JS实现，复用 figure-tools 图面样式和静态SVG导出辅助。它们不是通用自动布局引擎。模板适合时复用，不合适时按问题构图，不能改写内容语义。交互、动画和导出只在有阅读价值或交付需要时加入并验证。
