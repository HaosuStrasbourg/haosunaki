# HaosuNaki 组件与排版补充稿

2026-10-04 更新：六类组件与三个组合的最终展示版已确认，优先读取[已确认组件与组合](2026-10-04%20-%20已确认组件与组合.md)。本文件的长文规则不覆盖其中的紧凑组件字级；统一卡片圆角、密度及状态等旧建议不覆盖各组件已确认定义。评审页专属编号和章间线不自动推广到普通页面。

日期：2026-10-03。状态：工作建议与可验收的组件协议。

此前原则已获用户同意：英文正文继续使用 JetBrains Mono；图表逐张判断突出重点或平等比较；补齐页面网格、卡片组合、图表和表格规则。本轮新增的宽版心及换列阈值属于工作建议；内边距等沿用已有基准，可根据样张调整，不代表所有样张已经通过视觉验收。

纸白、钴蓝、陶珊瑚、莓红及五个字体用途保持 v1 基准。普通内容页不增加署名、Logo 或 HaosuNaki 落款。

## 1. 页面网格：先保证阅读，再给比较留出宽度

### 适用条件

- 页面默认使用同一条最大 720px 的阅读列。标题、正文、按钮组、普通卡片、简单图表及其图注沿共同边线排列。
- 只有复杂关系图或多字段比较表在正常字号下确实放不下、且扩大宽度有助于比较时，才启用宽内容区。先尝试合理换行或改为单列；不因出现图表、并排卡片或大屏幕就自动展开。
- 不以屏幕宽度为理由，自动把所有正文分成两列；同一论证保持单一路径。

### 组成结构

页面沿用原稿的标题、章节、段落及内容顺序，不按组件模板重排文章。外框负责页面留白，阅读列负责行长，比较区负责同级内容的排列。新增图内的来源、单位和条件就近标注；不为布局搬动原稿中的来源、条件或限制段落。

### 排列规则

| 对象 | 规则 | 确认状态 |
| --- | --- | --- |
| 阅读列 | 实际内容宽度最大 720px | 延续 v1 |
| 页面边距 | 桌面左右 48px，中等视口 32px，手机 24px | 延续 v1 |
| 宽内容区 | 实际内容宽度最大 1120px；内部连续正文仍最大 720px | 本轮建议 |
| 章节间距 | 桌面 64px，手机 48px | 延续 v1 |
| 对齐 | 同组标题、控件、图表和图注使用共同边线；宽内容独立成段，避免同一组内容内部反复切换宽度 | 根据样张反馈修正 |

内容宽度与页面内边距分别控制。边距从 48px 降到 32px 时，阅读列仍不超过 720px，避免正文行长反而变长。默认 `<main>` 保持阅读宽度。本页只是普通卡片或简单图表时，不使用 `main.layout-wide`。确有宽内容才显式启用宽布局；其中普通章节整体用 `.reading-column` 收拢，不能只收拢正文却把同组控件和分隔线留在宽区域。

### 手机与打印

手机先保留清楚的阅读顺序，再让同级内容逐项展开。不能为了维持桌面列数缩小正文。打印时按页面可用宽度重排；宽图和宽表需检查实际导出的分页与字号，不能以屏幕预览代替打印验收。

### 正例与反例

- 正例：结论、按钮、两张短方案卡和来源保持同一阅读宽度；只有需要多字段横向核对的独立比较区才考虑展开。
- 反例：一段解释被拆入两个并排卡片，读者必须左右来回寻找下一句；或者宽屏正文铺满 1120px。

方法参考：[IBM 2x Grid](https://www.ibm.com/design/language/2x-grid/) 的对齐与尺度体系。720px、1120px 和上述断点由 HaosuNaki 场景决定，不是 IBM 的指定值。

## 2. 卡片组合：独立单元有边界，连续正文保持开放

### 适用条件

步骤、方案、案例、摘要等能够独立理解的内容单元可以使用卡片。连续正文、逐段推理和大篇幅方法说明使用开放排版。卡片边界必须表达分组，不只承担装饰作用。

### 组成结构

一组卡片由共同标题、可选的共同说明和卡片网格组成。每张卡片包含标题、必要内容及可选的证据或操作；不要求每张卡都填入图标、数字、标签和按钮。

组件协议：`.card-group` 包含 `.card-grid > .content-card`。组标题位于网格前方，组容器自身不再画一层边框。

### 排列规则

- 默认只出现一层有边界的卡片。内部用小标题、留白与细分隔线分组；不要重复叠加边框、背景和圆角。
- 确有父子对象关系时才考虑第二层容器，先检查缩进与分隔线能否清楚表达关系。不能把“父子关系”当作常规嵌套理由。
- 说明性卡片默认最多两列。每列建议至少 320px，列间距建议 24px；组容器内容宽度不足 664px 时转为单列。依据实际容器宽度判断，不只看设备名称。
- 短指标可用三列；标签、单位或数值放不下时换行或减列，不缩小数值强行保持三列。
- 卡片建议内边距 24px，手机 20px；组间隙桌面 24px，手机 16px；圆角沿用 16px。
- 同行外框可以随最高内容自然等高。禁止固定高度截断正文、单行省略关键标题或用省略号藏住结论。
- 方案比较使用相同字段和字段顺序；空缺写清楚“未提供”或“不适用”。字段多、需要逐行横向核对时改用表格。
- 保持 DOM 顺序与视觉顺序一致，不用视觉重排制造不同的手机阅读顺序。
- 非交互卡片不出现暗示可点击的悬浮抬升或手形指针。确有操作时使用明确的链接或按钮。

### 手机与打印

手机转单列后保留标题、编号、字段标签和完整正文。短卡片打印时优先保持完整；卡片内容超过一页时允许合理分页，不能为了禁止分页而产生大片空白或内容溢出。实际分页仍需按成品检查。

### 正例与反例

- 正例：两个方案各有“适用场景／优势／限制”，共同标题置于卡片组外；手机按方案 A、方案 B 顺序展开。
- 反例：整章先套大卡片，再套方案卡，再套指标小卡；每层都有边框和背景，导致可用行宽不断减少。
- 正例：一段较长的结论与解释直接排在页面上，随后用卡片呈现两条独立行动。
- 反例：为凑齐两列，把同一段论证的前半段和后半段分别放进两张卡片。

方法参考：[Apple Boxes](https://developer.apple.com/design/human-interface-guidelines/boxes) 的分组与嵌套原则，以及 [Carbon Tile](https://www.carbondesignsystem.com/building-blocks/core/components/tile/guidelines) 的容器与交互区分。一层有界卡片、320px 最小卡宽及具体间距是 HaosuNaki 建议值。

## 3. 图表：逐张确定阅读任务，再选择颜色语义

### 适用条件

| 读者需要完成的任务 | 模式 | 颜色作用 |
| --- | --- | --- |
| 观察一个已明确的重点，并与参照对象比较 | `focus` | 没有领域色义冲突时默认蓝＋灰；已有语义色保留，以其他通道强调 |
| 平等比较多个类别，或连续追踪类别身份 | `category` | 按设计基准 §2 的区分度原则选择颜色，稳定绑定对象身份 |

没有明确单一重点时，不自动选择 `focus`。一篇文章可以同时包含两种模式，每张图必须显式标明自己的模式。不能因系列排在第一位、数值最大或最近一期，就自动把它设为重点。

表示数值高低的顺序色阶和基准偏差的发散色阶不属于上述分类策略；按设计基准 §2 先判断领域含义，再选择色阶，不以品牌偏好覆盖冷暖或金融语义，也不把无序类别色拼成数值阶。

### 组成结构

每张图包含图题、带模式声明的图形、直接标签、单位和来源；必要时补充口径及限制。已有解读保持原文，不自动撰写、压缩或改写；缺少解读时可单独提出补充建议。柱状图共用合理尺度，不能通过截断柱轴夸大差异。

HTML 组件协议：`figure` 内放 `.chart[data-chart="focus"]` 或 `.chart[data-chart="category"]`，其直系系列项为 `.chart-row`。

```html
<figure>
  <div class="chart" data-chart="focus">
    <div class="chart-row">参照对象</div>
    <div class="chart-row primary">明确的主要对象</div>
  </div>
  <figcaption>单位、来源与必要说明</figcaption>
</figure>

<figure>
  <div class="chart" data-chart="category">
    <div class="chart-row" data-series="plan-a" data-color="cobalt">方案 A</div>
    <div class="chart-row" data-series="plan-b" data-color="coral">方案 B</div>
  </div>
  <figcaption>单位、来源与必要说明</figcaption>
</figure>
```

### 排列与颜色规则

- 旧 `.chart` 模板的 `focus` 必须恰有一个 `.primary`，使用蓝＋灰。此模板不适合颜色已编码领域含义的图；这类图改用遵守设计基准的定制实现。
- `category` 不设 `.primary`。每个系列都有稳定的 `data-series` 标识及明确的 `data-color`，同一报告使用共同映射。
- 已确认基础色与冷静扩展的六个颜色键和色值见[设计基准 §2.2](2026-10-03%20-%20设计规范.md)。排序、筛选、增加或移除其他系列时，已有类别不换色。
- 同一报告的同一类别保持同色；不同分类维度的图可以复用已确认的类别色组，各自使用不混淆的类别标识。单张图内不同类别不能共用同一颜色。
- 禁止按 `nth-child`、当前数组下标或本次排序位置分配类别色。不同图中的相同类别保持相同颜色，标签变化不应改变稳定标识。
- 分类图按区分度选色，不受前三色顺序约束；类别多时优先分面、标签或表格，确需完整同图时不能循环颜色造成身份混淆。
- 灰色不表示不可用、低质量或没有价值；陶珊瑚、莓红不自动表示亏损、危险或错误。业务状态必须有明确的文字语义。
- 所有模式保留直接标签或清楚图例，不依赖颜色作为唯一识别渠道。

### 手机与打印

手机优先调整图形排列、分面或分组，标签保持可读，禁止把整张带文字的图缩到难以阅读。打印保留模式对应的标签与说明；黑白打印仍须能从文字或形状理解比较关系。真实 PDF 应检查图题、图形和图注的分页关系。

### 正例与反例

- 正例：文章明确研究“本次改版”，图中改版后数据为蓝色，历史方案为灰色参照。
- 反例：比较三种同等候选方案，却仅把得分最高的一个自动染蓝，提前暗示推荐结论。
- 正例：方案 A 在第一页和第五页均为钴蓝，即使第二张图改成降序排列。
- 反例：每张图都把第一行染蓝，导致同一类别在不同图中反复换色。

方法参考：[IBM 数据可视化基础](https://www.ibm.com/design/language/data-visualization/design/basics/) 对颜色与信息表达的指导。逐图模式、具体颜色以及 HTML 标识由 HaosuNaki 定义。

## 4. 表格：根据比较任务选择堆叠或横向对照

### 适用条件

- **简单记录表**：每一行可独立理解，手机逐条阅读即可，使用 `.table-wrap` 堆叠方式。
- **比较矩阵**：读者必须跨行、跨列核对相同字段，使用 `.table-scroll` 保留二维结构；提供局部横向滚动。
- 列数不是唯一判断标准。三列表格也可能必须保持横向比较，四列表格也可能适合逐条阅读。

### 组成结构

表格应有可识别的标题或 `caption`、语义表头和单位；列标题用 `th scope="col"`，行标题需要时用 `th scope="row"`。对齐先按列的语义决定，不能看到单个数字就切换对齐。单位写在行名或列名；同一数值字段统一计量口径与合理的小数位。

### 排列规则

- **混合内容的方案列**：当每列是一种方案、各行分别为时间、条件和说明时，表头、数字和文字统一左对齐，保持对象关联。不要把其中一行的数字单独推到列右边。
- **纯数值列**：整列都是同一指标、需要按位比较数量时，表头与数值采用同一右侧对齐线。统一单位与合理精度；编号、日期和版本号不是数量，默认按标签处理。
- **字形与对齐分别设置**：只需要 Georgia 数字字形时用 `.number`，不改变对齐；只有纯数值列才在该列的表头及单元格使用 `.numeric`。手机堆叠后数值与字段标签一起回到左对齐。
- 同级方案列默认分配相近的宽度。长说明允许换行；不通过拉大整张表或把数字推向列边缘补偿内容长度差异。
- 简单表使用 `.table-wrap > table`。需要在手机显示的列名写入相应单元格的 `data-label`，其文字必须与真实列标题一致，修改表头时同步更新。
- 比较矩阵使用 `.table-scroll > table`。滚动容器可通过键盘聚焦，具有可见焦点与清楚的无障碍名称；附近提供“可左右滚动查看完整表格”等提示。
- 手机堆叠后，先呈现该行对象名，再按原列顺序呈现字段。不能让一组数值失去行对象或列名。
- 行高由内容自然决定。长文字允许换行，关键内容不截断、不省略，也不依赖悬停才能查看。
- 缺失值、不适用和零值分别表达；例如“未提供”“不适用”和 `0`，避免统一用短横线混淆。
- 行和列重排后保留稳定的对象身份。比较方案使用一致字段顺序；强调色只标记有说明的重点，不把每个单元格都做成彩色卡片。

### 手机与打印

简单表逐行堆叠但保留全部信息；比较矩阵只在表格容器内横向滚动，页面主体不能跟着溢出。键盘检查应覆盖聚焦、滚动和离开容器。

打印取消滚动裁切，优先以完整表格显示并重复表头。超宽矩阵应根据内容采用横向页面、按列分组或附录等方案，保留比较关系和单位；不能静默裁掉右侧列，也不能无限缩小字号。具体策略及分页以实际 PDF 检查为准。

### 正例与反例

- 正例：三条资料各自列出名称、日期和来源，手机逐条堆叠，字段标签齐全。
- 正例：五个方案的八项能力使用横向滚动矩阵，读者可以沿同一字段比较，滚动区域有提示。
- 反例：把比较矩阵拆成五张长卡，读者每比较一个字段都要上下寻找；或者手机隐藏“限制”列节省空间。

## 5. 本轮验收边界

规范示例使用真实内容或明确标注的演示内容。重点检查：

1. 默认章节的标题、按钮、内容与图注共享 720px 以内的左右边线；例外宽区有明确的内容需要，不只检查正文行长。
2. 卡片按容器宽度减列，手机顺序与桌面一致，长内容不裁切。
3. 同页同时包含 `focus` 与 `category` 时互不干扰；类别重排后颜色不变；缺失模式或非法映射能够被发现。
4. 混合方案列的表头、数字和文字左边线一致；纯数值列的表头与数值右边线一致。简单表堆叠后字段齐全；复杂表只在局部滚动，键盘可操作。
5. 在桌面、390px 和 320px 宽度实际渲染检查；未检查的设备、打印分页和交互明确标注。

这些项目是本轮的验收要求，不是已经完成的测试声明。PDF 打印行为属于待按成品验证的规则，不承诺任意内容自动获得正确分页。
