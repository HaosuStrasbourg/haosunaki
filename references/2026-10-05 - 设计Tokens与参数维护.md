# 设计 Tokens 与参数维护

共用设计参数存放在 `assets/design-tokens.json`。已有页面构建器和基础 SVG 工具读取同一份参数，避免颜色、字体、组件密度和线条设置在多个文件里各改一遍。本文件指导维护，不要求普通生成任务读取全部参数。

## 参数、规则和样例各自负责什么

- **参数**保存可复用值及用途：纸白页面、白色节点、强调色、类别色、状态色、字体、字号、组件间距、圆角、线宽与透明度。
- **规则**决定什么时候用：重点与平等分类的选择、业务颜色优先、真实分支、图类选择、模块组合等，继续以设计基准和专项参考为准。
- **样例**帮助检查实际效果。参数一致不代表数据、布局或可读性已经通过验收；复杂构图仍须单独处理。

当前为内部格式 `haosunaki.tokens.v1`，不是完整 DTCG 兼容承诺；仅使用 Python 标准库，不引入构建依赖。

## 一个来源，两个主要消费者

| 文件 | 职责 |
|---|---|
| `assets/design-tokens.json` | 唯一的共用参数来源；包含类型、值或别名、用途、状态、CSS 映射和窄屏覆盖 |
| `scripts/design_tokens.py` | 校验并解析别名，输出 CSS 变量；错误引用、循环、类型冲突、重复映射直接报错 |
| `scripts/build_html.py` | 构建 HTML 时先注入参数，再加载组件结构 CSS；分类验证也读取此来源 |
| `scripts/figure_primitives.py` | 读取配色、图内字号及行高；换行测量读取相应字号；SVG 内嵌该次参数快照 |
| `assets/haosunaki.css`、`figure-tools.css`、`chart-theme.css` | 消费参数，负责实际组件与图形的样式结构 |

手动拼装 HTML 时必须同时注入 `design_tokens.render_css()` 和结构 CSS，不能再只拷贝 `haosunaki.css`。普通任务优先使用已有 `build_html.py`，无需另建构建流程。导出图形和页面是自包含快照；修改源参数后须重新生成，历史文件不会自动换肤。长驻 Python 进程须重新加载作图模块，避免保留旧值。

## 基础值与语义角色

例如 `palette.cobalt = #244AC7` 是基础值；`accent.primary` 和 `category.cobalt` 目前都引用它，但职责不同。改基础值会影响所有引用；只改强调角色则不应改变类别身份。`surface.page`、`surface.node`、`surface.emphasis` 和 `surface.callout` 分开维护，避免把相似颜色误认为同一种内容角色。

- 分类色按稳定对象 ID 映射；已有默认色序保持，不把清单顺序当成强制类别顺序。
- 业务含义、冷暖关系与类别区分优先于品牌配色；显式领域颜色覆盖仍有效。
- 状态、选中与类别分别定义；参数不自动把钴蓝解释为成功或把珊瑚解释为风险。
- 五类字体用途保留；字体回退是实现策略，不保证每台设备实际字形相同。本机字体仅引用，许可资源不改动。
- 不新增统一间距刻度来替换已确认组件。引用、指标、代码、提示框与标签保留各自参数；旧 `radius.legacy = 16` 只服务兼容样式。

## 确认状态与本轮变化

每项带 `status`：`confirmed` 表示来自已确认基础或组件样式，确认只覆盖原展示范围；`implementation` 表示实现值，未单独确认为通用标准；`legacy` 为历史兼容值。参数数量不等于独立完成用户评审的次数。

本轮修正普通流程节点为用户已明确要求的白底 `#FFFFFF`；纸白页面仍为 `#FAF8F4`。主网格保持 `1px / 0.105`，次网格使用 `0.6px / 0.03`。**“隔行、更淡更细”已确认；新增的 0.6px 是工作值，仍待视觉确认**，不得写成用户已批准的新数值标准。

图内辅助标注与图注分开：前者行高 20px，后者 22px。字体与行距修改必须一起检查真实显示尺寸；固定画布、基线和留白仍可能需要适配。此工具不是自动排版引擎，不承诺任何字号组合都不会溢出。

## 最小维护步骤

1. 判断改的是基础值还是某个语义角色；限定影响范围。涉及未确认的新审美决定，先做样本，不直接改成“已确认”。
2. 在 JSON 修改该项及适用的窄屏覆盖，保留中文用途与状态。别名使用完整 `{名称}`；尺寸为数值加 `unit: "px"`，不要写入 CSS 表达式。
3. 校验源文件，并重新生成受影响的页面与图形。桌面、手机和打印的覆盖是有意差异，不应直接抹平。
4. 核对真实渲染、长标签和必要交互。仅通过解析或几何检查时明确记录，不能宣称完成视觉验收。

读取接口（`SKILL_DIR` 为本 skill 目录）：

```sh
python3 "$SKILL_DIR/scripts/design_tokens.py" --help
python3 "$SKILL_DIR/scripts/design_tokens.py" --mapping
```

Python 接口：`load_tokens()` 读取带状态的原文，`resolve_tokens()` 获取扁平解析值，`token("surface.node")` 读取单项，`render_css()` 输出带窄屏覆盖的 CSS；生成独立 SVG 时使用局部作用域并关闭媒体覆盖，避免尺寸变化与固定几何脱节。

## 本次覆盖的边界

已接入：主要表面、文字和分类／数值／状态色，五类字体与主要角色字号，六类组件的常用间距和圆角，基础 SVG 网格、节点和边线。保留既有类名和生成入口。

未迁移为通用参数：所有历史模板的内部常量、每张定制图的坐标、每个标题层级和全部控件参数、历史定制图的快照样式（不随公开版分发）。已导出的旧稿不会自动更新；插画模型不能保证按 token 精确输出像素或色值。

公开包的核心检查入口为 `python3 -m unittest discover -s tests -v`；发布包检查不继承历史归档验收。整页浏览器视觉、320／390 窄屏、跨设备字体与 PDF 尚未验收，不能继承历史样张的检查结论。
