# HaosuNaki SVG 图表模板

2026-10-05 复用入口：最终已确认样例见[图族索引](2026-10-04%20-%20已确认图族与复用索引.md)，新数据的共用工具见[图形工具接口](2026-10-04%20-%20图形工具接口.md)。本文件中旧模板的限制只适用于该模板；不要把历史待评审措辞覆盖后续已确认样例。

日期：2026-10-03。支持六类图表：`bar`、`line`、`scatter`、`histogram`、`stacked`、`waterfall`。浏览器原生 SVG，无外部依赖、联网请求、动画、tooltip 或导出功能。示例数据均为虚构演示。

## 接入

页面加载 `assets/visuals.css` 与 `assets/visuals.js`；保留原有 HaosuNaki 字体与正文样式。每张图使用以下片段：

```html
<figure class="hn-visual">
  <h3>图题</h3>
  <p class="caption">单位、口径、时间范围</p>
  <div class="hn-plot"></div>
  <script type="application/json" class="hn-data">{ "kind": "...", "title": "...", "unit": "...", "mode": "..." }</script>
  <figcaption class="caption">来源、限制和必要说明</figcaption>
</figure>
```

页面就绪后自动绘制。动态修改 JSON 后调用 `window.HaosuNakiVisuals.renderAll()`，返回 `{total, ready, deferred, errors}`；`ready` 仅表示渲染未报告错误，不等于通过视觉验收。初始隐藏、宽度为 0 的图标记 `deferred`，不报错；容器显示后由 ResizeObserver 自动绘制。可传入 DOM 根节点只绘制该范围，但同类别跨图颜色一致性只对本次调用范围校验，整页验收应调用不带参数的版本。

JSON 数据必须合法。渲染器只使用 DOM 的 `textContent`、属性和 SVG 几何，不使用数据生成 HTML。将 JSON 内嵌于 HTML 时，生成方必须把字符串中的 `<` 转义为 `\u003c`，防止文字中的 `</script>` 提前关闭数据块；这属于 HTML 解析阶段，晚于解析的渲染器无法补救。

## 公共字段与颜色

以下是旧模板当前支持范围，不是规范的配色上限。若这些颜色键、蓝灰重点或固定增减色不满足设计基准 §2 的领域语义和区分度要求，使用已验证的定制实现；本次说明更新不代表渲染器已支持任意颜色。

每图必须有非空 `title`、`unit` 和显式 `mode`。可选 `summary` 是始终展开的核心解读，不放入折叠数据表；原作者的图题、图注也保持可见。未提供 `summary` 时仍显示图例与计量说明，但渲染器不替作者虚构结论。

| 模式 | 语义 | 必需字段 |
| --- | --- | --- |
| `single` | 一个测量序列，所有观测同等；不表示自动重点 | 条形图声明 `series:{id,label}`；折线、散点、堆积图只能有一个 series |
| `focus` | 作者明确指出一个关注对象，钴蓝；其余灰色 | `focusId` 必须精确命中该图对象 ID |
| `category` | 平等识别类别，单图最多六个类别 | 每个颜色对象明确稳定 `id`、`label`、`color` |

`category` 的 `color` 支持 `cobalt`、`coral`、`berry`、`lake`、`lavender`、`tea`（色值见设计基准 §2.2）；同图不得重用，相同 ID 在同页不得改变颜色。不同分类维度使用不同 ID 命名空间。不按数组下标、最大值或首项推断重点。focus 的颜色对象：条形图为 `data` 项，其余支持该模式的图为 `series`。直方图、瀑布图只接受 single；瀑布图在单一余额序列内使用单独说明的正负方向色，不表达类别或重要程度。

## 六类数据结构

下列 JSON 均为可直接使用的完整虚构演示，包含公共字段。完整 figure 示例见 `chart-demo-fragment.html`。

### bar：单一量纲条形图

```json
{"kind":"bar","title":"虚构演示：分数变化","unit":"分","mode":"focus","focusId":"b","data":[{"id":"a","label":"对象 A","value":-8},{"id":"b","label":"对象 B","value":12}]}
```

横向条形、纵向排列；所有值同尺度，必须含零基线，负值向左。single 另加 `series:{"id":"measure","label":"同一指标"}`；category 给每个 data 项明确颜色。标签直接显示数值与单位；零值保留零标记。

### line：真实间隔折线图

```json
{"kind":"line","title":"虚构演示：不规则间隔观测","unit":"次","mode":"single","xType":"number","xUnit":"天","series":[{"id":"observations","label":"观测","points":[{"x":1,"y":10},{"x":3,"y":null},{"x":10,"y":12}]}]}
```

`xType` 必须为 `number` 或 `time`。时间接受 `YYYY-MM-DD`，或带时区的 ISO 时间（如 `2026-01-01T12:00:00Z`），按 UTC 标示。每个序列的 x 必须严格递增，重复或乱序直接报错。y 只能是有限数值或显式 null，null 断开路径；每序列至少有一个实数。不平滑、不补值、不跨缺失连线。纵轴可以不含零，刻度明确展示实际数值范围。

### scatter：二维数值散点图

```json
{"kind":"scatter","title":"虚构演示：时长与评分","unit":"分","mode":"single","xUnit":"分钟","series":[{"id":"samples","label":"样本","points":[{"id":"p1","label":"样本 1","x":2,"y":5},{"id":"p2","label":"样本 2","x":7,"y":6}]}]}
```

公共 `unit` 是 y 单位，`xUnit` 是 x 单位，两者必须明确。每个系列非空，每个点包含唯一 id、label、有限数值 x/y；不接受 null。不自动绘制回归线。分类点使用圆／方／三角形及图例辅助区分。点坐标不做抖动，同坐标的观测可能重合，完整记录保留在数据表。

### histogram：由原始值计算频数

```json
{"kind":"histogram","title":"虚构演示：时长分布","mode":"single","unit":"频数","xUnit":"分钟","values":[1,2,4,6,8,9,11,14,18,20],"binEdges":[0,5,10,15,20]}
```

必须提供非空原始 `values` 和至少两个等距递增 `binEdges`。区间左闭右开，最后一箱右闭。原始值超出边界、不等宽分箱、非有限数值均报错。纵轴为数量频数，`unit` 仅接受“频数”“次”“个”；不支持密度。数据表同时展示原始值与实际计算的分箱统计。过密分箱不在柱顶强塞数字，但分箱统计保留完整。

### stacked：非负可加总堆积图

```json
{"kind":"stacked","title":"虚构演示：分项构成","unit":"件","mode":"category","stackMode":"percent","additive":true,"series":[{"id":"part-a","label":"分项 A","color":"cobalt"},{"id":"part-b","label":"分项 B","color":"coral"}],"data":[{"id":"group-1","label":"第一组","values":{"part-a":30,"part-b":20}}]}
```

`additive:true` 明确承诺分项口径一致、可相加；渲染器不能替作者验证业务口径。`stackMode` 必须为 `absolute` 或 `percent`，后者按每行总和归一化且拒绝总和为 0。只接受非负数，每行 values 必须完整且仅包含已声明系列 ID。保留原值、单位、合计和百分比直接标签；不把占比图误写为绝对量。

### waterfall：有核对的变化瀑布图

```json
{"kind":"waterfall","title":"虚构演示：余额核对","unit":"万元","mode":"single","start":{"id":"opening","label":"期初","value":100},"contributions":[{"id":"gain","label":"增加项","value":30},{"id":"cost","label":"减少项","value":-20}],"end":{"id":"closing","label":"期末","value":110}}
```

从上到下读取。必须显式给出 start、至少一个有符号 contribution 和 end；所有步骤 ID 唯一。核验 `start + sum(contributions) == end`（相对浮点容差 1e-9），不匹配直接报错。期初、期末从零延伸，变化条连接前后余额。旧模板当前增加为陶珊瑚且带 `+`，减少为钴蓝且带 `−`，期初／期末深色并有文字；方向色在图例和说明中明确声明。

## 响应式、可访问性与验收边界

- `ResizeObserver` 监听实际容器宽度，重算 SVG 像素几何；viewBox 与当前像素尺寸一致，不把桌面 SVG 整体缩小。极窄于 160px 的容器显示可读错误。没有 ResizeObserver 时用窗口 resize 作为兼容回退。
- 图中主标签固定 16px，辅助轴与单位 14px。文字使用 JetBrains Mono／PingFang SC；独立数值刻度使用 Georgia／Lora。条形、堆积、瀑布图的文字纵向换行，图高随内容增长。折线／散点在手机减少刻度密度。
- 每张 SVG 保留真实文本，使用 `role="img"`、title、desc；不用图片或 path 代替字。线宽 2px，辅助线 1px，无阴影、3D 或装饰渐变。
- 自动生成可展开的原始数据表，表头、字段、缺失值和单位完整；窄屏只在表格容器内滚动，容器可聚焦且有可访问名称。summary 和核心图解保持展开。
- 数据错误显示中文消息，figure 标记 `data-hn-status="error"`；不补猜字段，不静默过滤错误值。未知图型不降级为其他图型。
- `beforeprint` 尝试重算；打印版不是经过验收的 PDF。任意长数据、长标签、同坐标散点、过密分箱仍需按实际内容做视觉检查；不要宣称任意输入都已通过布局或 PDF 验收。
- 本子任务只执行 `node --check assets/visuals.js` 静态语法检查；桌面、390px、320px 的实际视觉检查由集成阶段完成。
