# HaosuNaki 方框连线图

2026-10-05 复用入口：最终已确认样例见[图族索引](2026-10-04%20-%20已确认图族与复用索引.md)，新数据的共用工具见[图形工具接口](2026-10-04%20-%20图形工具接口.md)。本文件中旧模板的限制只适用于该模板；不要把历史待评审措辞覆盖后续已确认样例。

适用于阅读型 HTML 中的简短流程、系统架构与对象关系。图示先讲清楚关系，再使用颜色强调；内容没有真实连线或层级依据时，先用文字澄清，不替作者猜测。以下尺寸是可调整的工作建议，不代表用户逐项确认。

先按[作图总则与选型路径](2026-10-03%20-%20作图总则与选型路径.md)判断是否适合方框连线。解释排队、时间间隔、并行、反馈或状态变化时，可选择机制图解；继承同一视觉语言，不要求所有机制都套成等大方框或直角连线。本模板仍只实现下述三类结构图。

本文件的固定层级、分组和连线限制属于内置模板接口，不约束定制SVG。遇到真实回路、嵌套作用域、时序或计算布局时，改按[定制SVG与交互实现](2026-10-03%20-%20定制SVG与交互实现.md)绘制。

## 1. 选哪一种图

| 阅读问题 | kind | 需要作者提供的语义 |
| --- | --- | --- |
| 下一步是什么，判断后如何分支？ | `flow` | 步骤、顺序、条件和明确方向 |
| 系统有哪些层，边界内包含什么？ | `architecture` | 显式层级、成员归属、接口关系 |
| 哪些对象相关，是什么关系？ | `relationship` | 对象、关系名称、是否有方向 |

一图围绕一个问题。阅读页通常以约 3–8 个主要节点为起点；这不是通用死限制，也不是渲染器的硬上限。节点、关系或交叉线明显增加时，优先拆成“总览＋局部图”，保留稳定名称。不要把复杂系统压成缩小后无法阅读的一张图。

### 按用途选择表达密度

先问：读者需要照图执行、检查每个分支，还是先理解它如何运作？建议按以下边界选择，而非按节点数、事情的重要程度或是否正式发布分类。

| 用途 | 执行型流程图 | 解释型轻量图 |
| --- | --- | --- |
| 读者任务 | 执行、审批、实现、排查；需要判断下一步怎么走 | 理解机制、角色协作、依赖与分合关系 |
| 内容要求 | 在声明范围内明确步骤、真实条件、输入输出、责任交接及异常／返回路径；有跨角色责任时才增加泳道 | 核心角色、处理阶段和真实关系；图内用短标签，解释就近放正文 |
| 视觉处理 | 为条件与必要说明留空间，节点尺寸随内容调整；不靠厚边或大框表达严谨 | 紧凑节点、较轻边线、充足外围留白；同类对象同样式，重点局部强调；保持可读字号与箭头间距 |

两类图共用语义规则：真实判断仍用菱形，明确分发与汇合，实线／虚线含义一致；不能为了轻量删掉会改变结论的分支、异常或反馈。只有真实流程才标起止，架构／关系图不强加开始和结束。细节移到局部图时，标明总览范围并提供对应说明。复杂研究报告可先给轻量总览，再给执行细节图。

**表达密度与交付阶段互相独立。** 执行型和轻量型均可正式发布；两者的调试编号都按 §2 控制。2026-10-05 用户认可轻量试稿方向；该样张的具体尺寸是实例参数，不强制推广到所有流程。

## 2. 节点和连线必须表达真实含义

### 2026-10-05 用户指定的流程布局规则

- **白底、轻边与居中。** 普通节点使用 `#FFFFFF`，与纸白页面区分；非强调节点用中性细边，只给明确强调或必要类别加色。正文按完整形状上下居中，角标不影响正文定位。
- **标准记法优先。** BPMN 的事件型网关、消息事件、顺序流与跨池消息沿用标准语义，不强行套成“是／否”条件或普通箭头；见已确认图族索引中的 BPMN 协作例。

- **真实条件判断用菱形。** 内部写判断问题，出线就近写“是／否”或互补的实际条件。连线优先从菱形顶点进出，一个顶点只出一根线；不要沿斜边任意接出多条线。普通步骤、并行分发，以及名称恰好为 Decision 的状态，都不自动变成判断菱形。
- **临时编号只服务调试／评审，正式稿默认移除。** 需要定位反馈时，给节点添加稳定短编号；矩形放左上角，菱形及圆形／胶囊放顶部居中安全区。编号与辅助标识叠放，不占正文行、不改变正文在完整形状中的上下居中，且不得相互重叠。正式稿默认不绘制这些编号，并将“返回 01”等临时引用改为完整节点名称；保留内部稳定 ID、节点名称、关系，以及真实业务编码或内容本身需要的步骤引用。普通有序列表的顺序序号不属于调试角标。编号不能替代名称，也不暗示并行对象间的执行依赖。
- **起止范围写清楚。** 用可辨的起止形状并明确写“开始／结束”及输入、输出；单轮算法写“本轮开始／本轮结束”，不能擅自补造整个任务的终止条件。用户允许起点、终点使用轻量色差：本例开始淡蓝、结束淡青，颜色只辅助辨认，不取代文字或自动表示成功／失败。具体浅色参数仍是本例呈现选择，不扩展为业务状态映射。
- **连线短、少弯折、少绕。** 先用一致阅读方向安排节点，优先水平／垂直连线、尽量不用斜线；分支就近展开、就近汇合。直线足够时不用绕路；必要直角折线优于斜接菱形非顶点。真实回路保留语义并避让文字。共享路径的汇合点明确显示，普通交叉不冒充汇合。单轮图可把继续执行说明为“将输出的新前缀送回草稿模型，开始下一轮”，不要用长回线包围整图；不得因此删掉循环含义。
- 新流程使用 `figure_primitives.flow` 的 `shape`、`number` 与 `terminal_kind` 接口，或同等定制 SVG；详见[图形工具接口](2026-10-04%20-%20图形工具接口.md)。以下旧 JS 模板仍按历史接口兼容，不会自动生成菱形、编号或起止形状，不作为新流程的首选。

### 旧 JS 模板的兼容接口

- `process`：普通步骤或对象，8px 圆角矩形。关系图中的普通对象也用此类型，不暗示流程顺序。
- `decision`：旧模板实现为带“判断”标签的矩形，仅供历史兼容。新流程按上面的规则绘制菱形，不沿用此旧形状。每条出线必须有条件 `label`，且明确 `directed: true`。
- `external`：虚线外框并标明“外部对象”。不把外部系统画进本系统边界。
- `group`：真实的边界容器，通过 `members` 声明成员；不占据流程步骤，也不能作为连线端点。边界不允许嵌套、成员重复归属或误包非成员。
- 连线连接边框；端点不悬空、不进入文字，不因布局方便更改 from/to。实线／虚线的具体业务含义写在图注中。
- `directed: true` 才有箭头；`false` 表示无方向关联。不得把普通关联自动解释成消息流、依赖方向或父子关系。
- 每张图使用显式 `levels`，数组顺序表示从上到下，每层内部从左到右。此排布不会新增语义：架构图的父子、边界必须有真实依据，关系图的上下位置可以仅服务于阅读。
- 尽量避免交叉线和过长回路；优先调整同层顺序或拆图。线条相交不自动表示交汇或共同节点，渲染器不会在交叉处创建节点。

## 3. 字体、颜色与间距

本节列出旧模板当前支持的颜色键；若不满足设计基准 §2 的业务语义或区分度要求，使用合适的定制实现，不以模板限制反向改变颜色含义。

| 项目 | 默认建议 |
| --- | --- |
| 图题 | 页面标题字体：中文 Songti SC，英文 IBM Plex Mono；22px／32px |
| 节点 | 中文 PingFang SC，英文 JetBrains Mono；16px／26px；自然换行 |
| 条件、类别、边界名 | 14px／22px；仅用于短标签 |
| 图注与滚动说明 | 14px／24px |
| 普通节点 | 宽约 200–224px，最小高 64px，内边距 16px／18px，圆角 8px |
| 同层节点间距 | 64px |
| 层间留白 | 普通图约 100px；带边界图约 120px，给条件和边界名留空间 |
| 连线与节点边框 | 2px；直线或直角折线 |
| 画布／节点底 | 纸白 `#FAF8F4`；分类对象采用已确认的 1C 描边，必要中性分组可用辅底 |
| 文字／线条 | 正文 `#282623`；辅助与边框 `#68635D` |
| 单一重点 | 显式 `focus: true`，钴蓝 `#244AC7`；不自动突出首项或最多关系的节点 |
| 类别 | 同时声明 category 与 color；支持 cobalt／coral／berry／lake／lavender／tea，精确色值见设计基准 §2.2；颜色不会按位置分配 |

一张图只选择“单一重点”或“分类配色”中的一种语义；未指定时保持中性色。分类配色必须保留可见类别文字，同一报告中的同一类别保持同色。陶珊瑚 `#C45C46` 与莓红 `#A33C62` 不默认表示错误或风险。无装饰图标、阴影或动画。

## 4. HTML 与 JSON 接口

在页面的基础 HaosuNaki 样式之后引入 `assets/diagrams.css`，再加载 `assets/diagrams.js`（可使用 defer 或内嵌到页面末尾）。无外部依赖，不自行下载字体或联网。

```html
<figure class="hn-diagram">
  <h3>阅读准备</h3>
  <p class="hn-diagram-description">示意结构 · 下一步取决于材料是否齐全。</p>
  <div class="hn-diagram-canvas"></div>
  <script type="application/json" class="hn-diagram-data">
  {
    "kind": "flow",
    "title": "阅读准备",
    "nodes": [
      {"id": "check", "label": "材料是否齐全？", "type": "decision"},
      {"id": "read", "label": "开始阅读", "type": "process"},
      {"id": "add", "label": "补充材料", "type": "process"}
    ],
    "levels": [["check"], ["read", "add"]],
    "edges": [
      {"from": "check", "to": "read", "label": "是", "line": "solid", "directed": true},
      {"from": "check", "to": "add", "label": "否", "line": "solid", "directed": true}
    ]
  }
  </script>
  <figcaption>示意结构。箭头表示下一步；实际规则以正文为准。</figcaption>
</figure>
```

`id` 是稳定的唯一字符串；修改显示名称时保留 ID。`levels` 必须包含每个普通节点恰好一次，不列入 group。`edges` 即使为空也必须明确写 `[]`。`directed` 必填，不设置隐含方向。`line` 默认 `solid`，`type` 默认 `process`；关系图的每条连线都必须有 `label`。

边界节点示例：

```json
{"id":"system","label":"内容系统边界","type":"group","members":["service","store"]}
```

类别节点示例：

```json
{"id":"source-a","label":"资料 A","type":"process","category":"外部资料","color":"coral"}
```

JSON 标签按纯文本渲染，不解释 HTML。把用户输入序列化进 HTML 的 JSON script 时，仍须将 `<` 转义为 `\u003c`，防止内容中的 `</script>` 提前结束脚本元素。不要手工拼接未经转义的 JSON。

脚本在页面就绪、字体加载完成及容器宽度变化时重排。手动更新 JSON 后调用：

```js
window.HaosuNakiDiagrams.renderAll();
// 也可只更新某个 figure：
window.HaosuNakiDiagrams.render(document.querySelector('figure.hn-diagram'));
```

`renderAll()` 返回每张图的 `{figure, ok}`，也可检查 `data-diagram-state="ready|error"`。`validate(data)` 返回标准化数据或抛出可读错误。缺失／重复 ID、无效端点、遗漏层级、缺条件的判断分支和不成立的边界会直接报错，不静默修复或生成假线。

## 5. 手机、无障碍与验收

- 简单流程默认纵向，手机继续按原顺序阅读。分支、并排结构和关系图保留真实拓扑；空间不足时只在图内横向滚动，并显示提示。
- 不缩小整张带文字图。节点仍用 16px，长文本自然换行；很长的解释放在图旁正文或图注中。
- 滚动区域可键盘聚焦，提供可见焦点。每张图都有等价“文字关系清单”，列出全部连线、边界和独立节点；清单不只复述图名。
- 没有 JavaScript 时建议在 `noscript` 内写出相同关系。图的含义不能只存在于颜色或悬停提示中。
- DOM 保持 levels 顺序。无 ResizeObserver 的浏览器使用窗口 resize 回退；现代浏览器在容器变化时自动重排。
- 实际检查桌面、390px 和 320px：节点文字完整、条件不压线、边框相连、页面无横向溢出、局部滚动与文字清单可操作。
- 脚本做节点避让并尽量减少同路段重叠；不承诺通用图布局最优。多重回路、密集关系或很长的标签应人工调整层级顺序或拆图，再作视觉验收。
- 打印不自动缩小或删掉图形；宽图打印可能超过纸张可用宽度。输出 PDF 前应专门调整分图／横向页面并实际检查，屏幕通过不等于 PDF 通过。

## 6. 宿主与字体边界

HTML 能加载这里的 CSS、脚本及字体资源，GitHub README 的普通 Markdown 不能承诺加载相同字体与 CSS。GitHub 中若需保留精确视觉，可提供经验证的图像和等价文字，并链接完整 HTML；这需要按本次交付要求选择，不是自动替换。

Mermaid 的布局、字体、主题、安全配置和宿主渲染版本各不相同。本模块不调用 Mermaid，也不承诺把同一数据改成 Mermaid 后外观或连线布局完全相同。中文字体依赖本机 PingFang SC／Songti SC 及回退字体，跨平台字形仍可能变化。
